# How the Delhi Sustainable Transportation Advisor works

The Delhi advisor compares door-to-door journeys by bus, Delhi Metro, local passenger train, and cab. The planner uses published schedules to find public transport connections, a trained model to improve travel times on one eastbound bus corridor, and road routing plus traffic assumptions to estimate cab time. It calculates the fare for each ticket or cab ride, combines those charges, and uses the traveller’s budget and preferences to rank the options. [Journey planner](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L203-L305)

The code links in this report point to GitHub commit `92256a0`.

## 1. From source and destination to route options

When a traveller submits the form, the React dashboard sends the origin and destination, requested departure in Indian Standard Time, allowed modes, budget, and priority to `POST /api/plan`. It also sends the selected walking limit, cab type, and fare discounts. The server validates the inputs and calls `Advisor.plan`. The frontend displays the times, fares, and estimate sources returned by the backend for each itinerary. The map background uses keyless OpenStreetMap tiles. ## 2. How the bus model learns and makes predictions

1. **Build a target from GPS traces.** The project filters and cleans historical Delhi bus GPS observations. For each valid traversal of a configured road segment, it interpolates when the bus crossed the entry and exit gates. The target is `(exit timestamp − entry timestamp) ÷ 60` in minutes. It keeps plausible trips, including a 1–45 minute duration range and an average-speed cap. Four directional segments across two roads yielded 637 labelled traversals from five days in July 2019. [GPS cleanup](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/data/cleaner.py#L59-L106) · [Traversal labels](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/features/label_generation.py#L175-L206) · [Modelling dataset](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/docs/FINAL_REPORT.md#L38-L50)
2. **Train from information available at entry.** The model uses the segment and route IDs, direction, segment length, time of day, rush-hour category, and features representing recent segment durations. At serving time the duration-history features have a fixed fallback derived from segment length at 22 km/h, with zero completed trips in the history count. This lets the same feature schema work from a stop, date, and time without a live GPS feed. Preprocessing one-hot encodes categorical fields and scales numeric fields. [Feature schema and cold-start values](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/features/build_features.py#L120-L178) · [Preprocessing](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/models/train.py#L67-L91)
3. **Choose and approve a model.** The training code compares regression candidates against a historical segment median and uses date-based splits to evaluate on later observations. The selected scikit-learn Gradient Boosting Regressor builds 100 shallow trees, each reducing errors from the earlier trees. Version 2 reuses that configuration with 510 training rows, adding another complete day to v1’s 408 rows. Its July 8 holdout mean absolute error (MAE) was **3.39 minutes**, compared with **3.62** for v1. Version 3 was evaluated at **3.56 minutes** and rejected. The registry records v2 as `champion` and v1 as `previous`, and MLflow mirrors those aliases. [Training and selection](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/models/train_cold_start.py#L30-L95) · [Gradient boosting settings](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/models/train.py#L94-L122) · [Version evidence](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/docs/results/phase3/phase3_summary.json#L229-L303) · [MLflow registry sync](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/versioning/mlflow_sync.py#L27-L104)

### How the dashboard uses the trained model

The dashboard’s backend loads the saved **v2 model** from the Phase 3 registry after checking the approval record, audit chain, and artifact hash. MLflow records the model versions and mirrors the champion alias. If the registry model is unavailable, the backend can try the local prediction service or an approved local bundle. Bus timetables provide the fallback for a leg without a usable prediction. [Model loading and fallbacks](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/bus_model.py#L77-L148) · [MLflow registry sync](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/versioning/mlflow_sync.py#L27-L104)

1. **Find a scheduled route.** The planner first finds a possible itinerary. It checks whether any bus leg covers the eastbound Outer Ring Road stretch from Chirag Delhi toward Nehru Place. The model API is approved for Route 90. The advisor can apply its estimate to other buses travelling the same stretch. [Approved API scope](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/src/api/main.py#L129-L166) · [Corridor matching](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/bus_model.py#L214-L237)
2. **Predict the time on the covered stretch.** The model receives the segment and scheduled entry time and predicts the full segment’s duration. The advisor multiplies it by the share of the segment the bus covers, capped at 100%. [Prediction and distance scaling](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/bus_model.py#L197-L237)
3. **Update the bus arrival and check connections.** The planner substitutes the new estimate for the scheduled time on that stretch. If the new arrival would miss a connection, the planner tries the next departure on the same route pattern. It drops that itinerary if no such departure remains. [Bus time substitution](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L572-L609) · [Downstream timing](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L611-L639)

```text
Adjusted bus ride time = original scheduled ride time
                       − scheduled time on the covered stretch
                       + model time scaled to the covered stretch
```

In a local run for **North Point (Nursing Home) → Pumposh Enclave** at **17:10 IST** on 23 November 2026, the planner found bus **511A down** entering at 17:11. The ride covered 93% of the modelled segment. The planner used **6.0 minutes** from v2 for the covered stretch compared with **10.2 minutes** in the timetable. The complete option took **11.2 minutes** and cost **₹10**. In the dashboard, the **ML bus estimate** label identifies an option that used the model. Open its itinerary to see the model version and the two times side by side. [Route badge](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/web/src/components/Journey.jsx#L55-L62) · [Model time and timetable time](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/web/src/components/Journey.jsx#L227-L236)

On the July 2019 holdout, the corridor’s MAE was **1.03 minutes** across 36 observed traversals, compared with **1.27** for the historical median and **4.09** for the timetable estimate. These figures measure historical bus segment error. The project does not have observed multimodal door-to-door times for a corresponding accuracy calculation. [Corridor evaluation](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/docs/FINAL_REPORT.md#L103-L125)

## 3. How the planner combines travel times

The route search uses RAPTOR, a round-based public transport routing algorithm. Each round considers another vehicle boarding. At a stop, it picks a scheduled departure the traveller can catch after arriving and allowing for the applicable boarding buffer. A transfer walk advances the arrival clock before the next boarding. The defaults include up to five public transport rides, a four-hour boarding search window, and these boarding buffers. [Route search](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/raptor.py#L65-L151) · [Boarding rules](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/raptor.py#L40-L53) · [Time configuration](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L12-L34)

| Activity | Calculation |
| --- | --- |
| Walk | Straight-line distance × 1.3, converted to time at 4.5 km/h. The default access radius is 1 km and can expand when the planner finds no nearby stops. |
| Board or change vehicles | Bus boarding uses a 1-minute buffer. Metro needs 5 minutes from the street or 4 minutes for an interchange. Train needs 6 minutes from the street or 5 minutes between trains. The displayed wait already includes the buffer. |
| Ride bus, metro, or train | Arrival minus departure, with the bus corridor correction when applicable. |
| Take a cab | Pickup wait plus OSRM driving time × traffic multiplier. If road routing is unavailable, estimated road distance is straight-line distance × 1.35 and the base driving speed is 38 km/h before applying the multiplier. |

The backend calculates **trip duration = final arrival − suggested leave time** from second-level timestamps. It can suggest leaving after the requested time to meet the first departure. That time before leaving is reported separately as `wait_after_departure_min`. The trip duration includes walking, boarding and transfer waits, time on vehicles, and cab pickup. Times shown on the clock and leg durations are rounded for display. [Suggested leave time and per-leg timing](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L396-L480) · [Total trip duration](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L481-L493) · [Cab traffic and pickup assumptions](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L182-L238)

For **Narela → Old Delhi**, a local run requested at **07:00** found the train scheduled for **07:44**. The planner suggested leaving at **07:38**, allowing 6 minutes to board. It arrived at **08:45**, so the reported trip took **67 minutes** and cost **₹10**. The 38 minutes before 07:38 bring elapsed time from the original request to 105 minutes. ## 4. How fares are calculated

| Mode | Fare rule implemented in the advisor |
| --- | --- |
| Bus | One fare per boarding. Use the positive Delhi Open Transit Data stage fare for the exact route and stop pair if available. Otherwise use ₹5 through 4 km, ₹10 through 10 km, or ₹15 above 10 km. If the traveller selects the eligible women’s free bus option, the configured bus fare is ₹0. [Bus fare rules](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L554-L562) |
| Metro | Use the total distance covered by one ticket. Consecutive rides that connect at the same metro station share a ticket, so the next leg shows ₹0. Distance bands are ≤2, ≤5, ≤12, ≤21, ≤32, and >32 km. Standard fares are ₹11, ₹21, ₹32, ₹43, ₹54, and ₹64. Sunday fares are ₹11, ₹11, ₹21, ₹32, ₹43, and ₹54. The smart-card option applies 10% off the ticket. Airport Express currently uses the standard metro table, which can understate its fare. [Metro fare tables](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L36-L62) · [Ticket and discount logic](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L524-L553) |
| Train | One assumed ordinary unreserved fare per rail boarding. ₹10 through 50 km and ₹15 above 50 km. [Train fare settings](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L79-L88) |
| Cab or auto | AC taxi costs ₹40 for the first 1 km plus ₹20/km thereafter. Non-AC taxi is ₹40 for the first 1 km plus ₹17/km. Auto is ₹30 for the first 1.5 km plus ₹11/km. The calculator adds 25% when the expected ride begins after pickup between 23:00 and 04:59, then rounds to a whole rupee. These are meter-based estimates. [Cab prices](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L240-L272) · [Cab pickup and pricing time](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L320-L342) · [Meter calculation](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/cab.py#L144-L153) |

**Total fare = public transport ticket charges + cab charges.** The planner rounds the sum to one decimal place. Walking and waiting add no fare, and the cab fare is per vehicle. The configured price covers the meter calculation and night surcharge. Booking fees, surge pricing, and tolls fall outside the estimate. [Fare aggregation](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L415-L487)

### Worked example with Metro and cab

For **Mayur Vihar Phase I → ITO**, requested at **10:00** on Monday 23 November 2026, the planner returned this option with the smart-card discount and the offline cab estimate.

| Leg | Estimated time | Fare |
| --- | --- | ---: |
| Walk to the Pink Line | 9.0 min walking | ₹0 |
| Pink Line | 5.0 min waiting + 1.6 min riding | ₹28.80, charged once for both Metro legs |
| Blue Line | 5.2 min waiting + 9.2 min riding | ₹0, included on the same ticket |
| AC taxi to ITO | 9.0 min pickup + 4.5 min driving over an estimated 1.59 km | ₹52.00 |
| **Total from suggested leave** | **43.7 min**, shown as 44 min in the demo | **₹80.80** |

The Metro distances are approximately **0.76 + 5.23 = 5.99 km**, so the standard ticket is **₹32** and the smart-card price is **₹32 × 0.90 = ₹28.80**. The AC taxi charge is **₹40 + (1.59 − 1) × ₹20**, or **₹52** after rounding. The cab portion’s 4.5-minute drive comes from roughly 2.5 minutes at free-flow speed multiplied by 1.8, with pickup counted separately. The same request can also produce a Metro-only option of **40 minutes for ₹28.80**. [Recorded journey and alternatives](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/docs/DEMO_CASES.md#L125-L143)

## 5. How the budget and sustainability affect ranking

The planner removes duplicate candidates and filters out weaker options by comparing arrival time, price, changes, estimated emissions, and walking distance. The selected priority determines the remaining options’ scores. Balanced uses `fare + 0.7 × trip minutes + 5 × vehicle changes + 20 × CO₂ kg + 0.6 × walking metres ÷ 100`. Cheapest puts more weight on rupees, Fastest on minutes, and Greenest on CO₂. The separate fastest badge identifies the earliest arrival. [Priority weights](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L28-L34) · [Scoring and option labels](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L641-L715)

Options within the budget rank first. The direct cab can still appear as an over-budget comparison. If every option exceeds the budget, the result states the cheapest fare and the extra amount required. For example, in an offline run for **Lajpat Nagar → Karol Bagh** at **19:35** with all modes enabled and a **₹40** budget, a ₹15 bus and a ₹28.80 Metro option fit, and the **₹269** direct cab appeared as a comparison. The ranked results come from a bounded search, so the reported cheapest option is the cheapest candidate considered for that request. [Budget handling and results cap](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/planner.py#L676-L725)

The emissions estimate multiplies distance by configured per-passenger-kilometre factors of **0.040 kg CO₂ for bus, 0.025 for Metro, and 0.020 for train**. The cab calculation divides estimated vehicle emissions by an assumed occupancy. These factors let the dashboard compare journeys on the same basis alongside fare and time. The prototype’s timetables, road traffic factors, and fare rules should be read as estimates from the pinned feeds and assumptions. [Emissions assumptions](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/config/advisor_config.json#L90-L101) · [Cab emissions](https://github.com/vedanth-04/AI-Powered-Sustainable-Transportation-Advisor/blob/92256a0491e1c08df82c373b073b270736ab5203/advisor/cab.py#L155-L157)
